# Tech Associate Hackathon — Team Repo

This repo starts intentionally blank of the assignment. Once you receive the business brief, use the files here to turn intent into working software without letting the build outrun the spec.

## Files
- `spec.md` — what problem you are solving, for whom, what success means, acceptance criteria, constraints, assumptions, and what is out of scope.
- `plan.md` — the current technical approach derived from the spec.
- `tasks.md` — the ordered build work derived from the spec and plan.
- `CLAUDE.md` — standing rules for the AI coding partner.
- `metrics.md` — lightweight learning and delivery capture.
- `skills.md` — reusable AI prompts/workflows worth keeping.
- `AI-STARTER-PROMPT.md` — a neutral first prompt to begin spec-first.

## Non-negotiables
1. `spec.md` is the source of truth for intent and acceptance.
2. Do not invent requirements or values. Unknowns stay explicit.
3. If the build and the spec disagree, resolve it in the files — never silently.
4. Do not build out-of-scope work unless the spec changes first.
5. Human review and verification own what ships.

Everything else — your design choices, how you collaborate, how you use AI, and how you solve the brief — is yours.
