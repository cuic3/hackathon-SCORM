# AI Starter Prompt — Spec First

Paste this after you receive the business brief:

> Read the business brief and `spec.md` before doing anything else.
>
> Help us make the problem and intended behavior precise **before** we discuss architecture, tasks, or code. Ask us one question at a time. Focus on what is still ambiguous about the user, outcome, acceptance criteria, constraints, edge cases, assumptions, and out-of-scope boundaries.
>
> Do not invent missing requirements or business facts. If we do not know something, keep it explicit as an open question or named assumption.
>
> As our answers become clear, update `spec.md` so it reflects what we actually mean. Challenge acceptance criteria that are subjective or not testable.
>
> Do not propose implementation or write code until we explicitly say the spec is Ready.
>
> After we declare it Ready, use the spec as the source of truth for any technical plan or task breakdown. If later learning conflicts with the spec, stop and surface the conflict rather than silently working around it.

This prompt intentionally does **not** tell the AI what solution to build or prescribe how the team should solve the brief.
